# Viberacy

**AI 답변 속 어려운 용어를 클릭하면, 그 문단의 문맥에 맞는 뜻을 쉬운 말로 알려 주는 브라우저 확장 프로그램**

Viberacy = **Vibe**coding + lite**racy**

> 현재 상태: **설계 완료, 구현 시작 전.** 전체 설계는 [설계 문서](docs/superpowers/specs/2026-09-19-viberacy-design.md)에 있습니다.

## 무엇을 해결하는가

기술 발전이 사회적 합의보다 앞서 나가면 **윤리적 공백**이 생깁니다. 같은 일이 에이전트와 사용자 사이에서도 벌어집니다. 에이전트는 전문용어로 말하고, 사용자는 그 뜻을 모른 채 개발을 이어 갑니다. Viberacy는 이 틈을 **"CS적 공백"**이라고 부르고, 이 공백을 줄이는 것을 목표로 합니다.

바이브코딩이 퍼지면서 비전공자 개발자가 크게 늘었습니다. 용어를 모를 때마다 따로 검색하거나 에이전트에게 다시 물어보면 작업 흐름이 끊깁니다. Viberacy는 **답변을 읽던 자리에서** 용어를 누르기만 하면 되도록 만듭니다.

### 실제로 겪은 예시

교내 SW·AI 융합연구개발에서 "AI 에이전트 스킬 공급망 보안" 주제를 진행하던 중 에이전트가 준 답변입니다.

> 카나리만 사용합니다. 모든 "공격"은 실제 피해 없이 `_canary_output/hits.log`에 한 줄 남기는 것으로 끝냅니다. … 정적 탐지기가 볼 수 있게, 그러나 무해하게. … 택소노미 4칸을 덮습니다.

"카나리", "정적 탐지기", "택소노미"를 모르면 이 문단은 읽을 수 없습니다. 게다가 **"카나리"는 뜻이 하나가 아닙니다.** 배포에서는 새 버전을 일부 사용자에게만 먼저 내보내는 방식을, 보안에서는 건드리면 흔적이 남는 미끼를 말합니다. 이 문단에서는 보안 쪽 뜻입니다.

즉 단어만 보고 뜻을 정할 수 없고, **문맥을 함께 읽어야 합니다.** 이것이 Viberacy가 사전만으로 끝내지 않는 이유입니다.

## 어떻게 작동하는가

사전과 LLM이 역할을 나눠 맡습니다.

| | 하는 일 | 특징 |
|---|---|---|
| **사전** (JSON) | 답변에서 용어를 찾아 밑줄을 긋고, 기본 뜻을 보여 준다 | LLM 호출 없이 즉시 동작하고 비용이 들지 않는다 |
| **LLM** (Claude Haiku 4.5) | 사전의 뜻 후보 중 이 문단에 맞는 것을 고르고, 쉽게 풀어 설명한다 | 사전이 근거가 되므로 지어내는 설명이 줄어든다 |

사용자가 보는 흐름은 이렇습니다.

1. AI 답변이 끝나면 사전에 있는 용어에 점선 밑줄이 생깁니다.
2. 용어를 클릭하면 팝업이 **즉시** 뜨고 사전 뜻이 먼저 보입니다.
3. 곧이어 "이 문단에서는 이런 뜻입니다"라는 문맥 설명이 이어서 나타납니다.
4. 사전에 없는 단어는 드래그해서 물어볼 수 있고, 답을 받은 뒤 **내 사전에 추가**할 수 있습니다.

사전은 이렇게 **사용자가 실제로 몰랐던 단어 중심으로 자랍니다.**

## 구조

```
┌─ claude.ai 페이지 ───────────────────────────┐
│  content script                               │
│   ├ answerWatcher   : 답변 완성 감지           │
│   ├ highlighter     : 사전 용어에 밑줄          │
│   ├ selectionTrigger: 드래그 → "?" 버튼         │
│   └ popup (Shadow DOM): 뜻 + 문맥 설명 표시     │
└───────────────┬───────────────────────────────┘
                │ chrome.runtime Port (스트리밍)
┌───────────────▼───────────────────────────────┐
│  background service worker                     │
│   └ explainTerm(): API 키 보관, Claude 호출     │
└───────────────┬───────────────────────────────┘
                ▼  Anthropic API (Haiku 4.5)

options page : API 키 입력, 사용자가 추가한 용어 목록
dictionary   : data/dictionary.json (기본) + chrome.storage.local (사용자 추가)
```

**꼭 지킬 세 가지 규칙** (자세한 이유는 설계 문서 3절에)

1. **LLM 호출은 `explainTerm` 한 곳에서만** 합니다. 나중에 백엔드 서버 경유로 바꿀 때 이 함수 내부만 고치면 되도록 하기 위함입니다.
2. **API 키는 background service worker에서만** 다룹니다. content script는 웹페이지와 같은 환경에서 돌기 때문에 키가 노출될 위험이 있습니다.
3. **claude.ai DOM 선택자는 `answerWatcher` 한 파일에만** 둡니다. 사이트 구조가 바뀌어도 한 파일만 고치면 됩니다.

## v1 범위

**포함**

- claude.ai 전용 Chrome 계열 브라우저 확장 (Manifest V3)
- 자동 밑줄 + 드래그 질문
- Claude Haiku 4.5, 사용자 본인 API 키 방식(BYOK)
- 기본 사전 150~300개 (AI/LLM, 보안, 개발 기초)
- 사용자 용어 추가, 설정 페이지

**이후 검토**

- 백엔드 서버 경유 LLM 호출 (설치만 하면 바로 쓸 수 있게)
- ChatGPT 등 다른 사이트 지원
- "이미 아는 용어" 숨기기
- 확장 프로그램 스토어 배포

## 기술 스택

TypeScript, Vite, Manifest V3, Vitest. UI 프레임워크는 쓰지 않습니다. 팝업 하나 정도는 일반 DOM으로 충분합니다.

## 함께 만들기

아직 코드가 없습니다. 참여하시려면 먼저 [설계 문서](docs/superpowers/specs/2026-09-19-viberacy-design.md)를 읽어 주세요. 대화로 정한 결정마다 **왜 그렇게 정했는지**를 함께 적어 두었습니다.

다시 논의하고 싶은 결정이 있으면 Issue를 열어 주세요. 가장 논의할 만한 지점은 아래 세 가지입니다.

- **사전을 어떻게 키울 것인가** — 사용자마다 따로 쌓을지, 모아서 공용 사전으로 만들지
- **BYOK vs 백엔드 서버** — 비전공자에게 API 키 발급은 진입 장벽입니다
- **초기 사전의 분야와 품질 기준** — 저작권 있는 용어사전의 문구는 쓸 수 없습니다

작업 방식:

- 브랜치: `feat/<기능>`, `fix/<버그>`, `docs/<주제>`
- 커밋: `feat: …`, `fix: …`, `docs: …` (Conventional Commits)
- 기능 브랜치에서 작업하고 Pull Request로 합칩니다
- **API 키를 절대 커밋하지 않습니다.** 키는 실행 중 `chrome.storage`에만 둡니다
