# Viberacy 설계 문서 (v1)

- 작성일: 2026-09-19
- 상태: 설계 승인됨, 구현 계획 작성 전

## 1. 목적

Viberacy는 Vibecoding과 literacy를 합친 이름이다.

바이브코딩이 확산되면서 비전공자 개발자가 크게 늘었다. 이들은 AI 에이전트가 내놓는 답변 속 코딩 용어, 논문 용어, AI·SW 전반의 용어를 모른 채 개발을 이어 간다. 기술 발전을 사회적 합의가 따라가지 못해 생기는 틈을 "윤리적 공백"이라고 부르듯이, 에이전트가 말하는 수준과 사용자가 이해하는 수준 사이에도 틈이 생긴다. Viberacy는 이 틈을 **"CS적 공백"**이라고 부르고, 이를 줄이는 것을 목적으로 한다.

용어를 따로 검색하거나 에이전트에게 다시 물어보면 작업 흐름이 끊긴다. Viberacy는 사용자가 답변을 읽는 자리에서 용어를 누르기만 하면, 그 문단의 문맥에 맞는 뜻을 쉬운 말로 보여 준다.

### 동기가 된 예시

"AI 에이전트 스킬 공급망 보안" 연구 중 에이전트가 준 답변의 일부:

> 카나리만 사용합니다. 모든 "공격"은 실제 피해 없이 `_canary_output/hits.log`에 한 줄 남기는 것으로 끝냅니다. … 정적 탐지기가 볼 수 있게, 그러나 무해하게. … 택소노미 4칸을 덮습니다.

여기서 "카나리", "정적 탐지기", "택소노미"는 비전공자가 이해하기 어렵다. 특히 "카나리"는 보안(미끼 토큰)과 배포(일부 사용자 선공개)에서 뜻이 다르므로, 사전만으로는 부족하고 문맥 판정이 필요하다.

## 2. 핵심 결정 사항

| 항목 | 결정 | 이유 |
|---|---|---|
| 동작 환경 | Chrome 계열 브라우저 extension (Manifest V3) | 터미널이나 다른 extension의 채팅 패널은 외부에서 텍스트를 꾸밀 수 없다. 웹페이지 DOM은 가능하다 |
| 지원 사이트 | claude.ai 하나 | 직접 매일 테스트할 수 있고, 사이트별 DOM 대응 부담이 가장 적다 |
| LLM 호출 | 사용자 본인 API 키(BYOK) | 서버 없이 바로 만들 수 있고 운영 비용이 없다. 이후 백엔드 서버 경유로 전환할 수 있게 경계를 둔다 |
| 모델 | Claude Haiku 4.5 (`claude-haiku-4-5-20251001`) | 짧은 설명을 빠르고 저렴하게 만들 수 있다 |
| 사전 구축 | 좁은 분야로 시작하고, 사용 중 모르는 용어를 추가하며 키운다 | 사용자가 실제로 모른 단어 중심으로 사전이 자란다 |
| 상호작용 | 자동 밑줄과 드래그를 함께 쓴다 | 사전에 있는 용어는 알아서 알려 주고, 없는 용어는 드래그 경로로 물어본 뒤 사전에 추가한다 |

### 사전과 LLM의 역할 분담

- **사전**: 용어 감지(밑줄)와 기본 뜻 제공을 맡는다. LLM 없이 즉시 동작한다.
- **LLM**: 사전의 뜻 후보 중 문맥에 맞는 것을 고르고, 그 문단에 맞춰 쉽게 풀어 설명한다. 사전이 근거 역할을 하므로 지어내는 설명이 줄어든다.

## 3. 구조

```
┌─ claude.ai 페이지 ───────────────────────────┐
│  content script                               │
│   ├ answerWatcher   : 답변 완성 감지           │
│   ├ highlighter     : 사전 용어에 밑줄          │
│   ├ selectionTrigger: 드래그 → "?" 버튼         │
│   └ popup (Shadow DOM): 뜻 + 문맥 설명 표시     │
└───────────────┬───────────────────────────────┘
                │ chrome.runtime Port (스트리밍)
┌───────────────▼───────────────────────────────┐
│  background service worker                     │
│   └ explainTerm(): API 키 보관, Claude 호출     │
└───────────────┬───────────────────────────────┘
                ▼  Anthropic API (Haiku 4.5)

options page : API 키 입력, 사용자가 추가한 용어 목록
dictionary   : data/dictionary.json (기본) + chrome.storage.local (사용자 추가)
```

| 구성 요소 | 하는 일 | 의존하는 것 |
|---|---|---|
| `answerWatcher` | claude.ai 답변 영역을 `MutationObserver`로 지켜보다가 스트리밍이 끝나면 알린다 | claude.ai DOM 선택자 (이 파일에만 둔다) |
| `dictionary` | 용어 목록 로드, 텍스트 안의 용어 찾기, 뜻 조회, 사용자 항목 추가 | JSON, `chrome.storage.local` |
| `highlighter` | 답변의 텍스트 노드에서 용어를 `<span>`으로 감싸 밑줄을 긋는다 | `dictionary` |
| `selectionTrigger` | 드래그한 텍스트 옆에 "?" 버튼을 띄운다 | 없음 |
| `popup` | 사전 뜻을 즉시 보여 주고, 그 아래에 스트리밍 설명을 이어 붙인다. Shadow DOM으로 claude.ai CSS와 격리한다 | background와 Port 통신 |
| `explainTerm` | 프롬프트 구성, Claude 호출, 결과 스트리밍 | API 키 |

### 기술 스택

TypeScript, Vite, Manifest V3. UI 프레임워크는 쓰지 않는다.

### 설계 규칙

- **LLM 호출은 `explainTerm` 한 곳에서만 한다.** 백엔드 서버로 전환할 때 이 함수 내부만 바꾸면 되도록 하기 위함이다. provider 추상화 계층은 만들지 않는다.
- **API 키는 background service worker에서만 다룬다.** content script는 웹페이지와 같은 환경에서 돌기 때문이다.
- 브라우저에서 Anthropic API를 직접 호출하므로 `anthropic-dangerous-direct-browser-access: true` 헤더를 붙인다.
- **claude.ai DOM 선택자는 `answerWatcher` 한 파일에만 둔다.**

## 4. 사전 데이터 형식

```json
{
  "id": "canary",
  "aliases": ["카나리", "카나리아", "canary", "canary token"],
  "senses": [
    {
      "id": "canary.security",
      "domain": "보안",
      "short": "건드리면 흔적이 남도록 심어 둔 미끼",
      "easy": "탄광에서 유독가스를 먼저 알아채려고 데려가던 카나리아 새처럼, 문제가 생기면 먼저 신호를 보내는 장치입니다."
    },
    {
      "id": "canary.deploy",
      "domain": "배포",
      "short": "새 버전을 일부 사용자에게만 먼저 내보내는 방식",
      "easy": "새 메뉴를 전 지점에 내놓기 전에 한 지점에서만 먼저 팔아 보는 것과 같습니다."
    }
  ]
}
```

- `aliases`: 한글 표기, 영어 표기, 흔한 변형. 밑줄은 이 목록을 기준으로 긋는다.
- `senses`: 뜻이 하나뿐이면 원소도 하나다. `short`는 팝업에 즉시 보여 줄 한 줄 설명, `easy`는 비유를 곁들인 쉬운 설명이다.
- 사용자가 추가한 항목도 같은 형식으로 `chrome.storage.local`에 저장한다. 기본 사전과 분리해 두므로 extension을 업데이트해도 덮어써지지 않는다.

### 용어 찾기 규칙

1. 긴 alias부터 찾는다. "정적 탐지기"가 "정적"보다 먼저 잡힌다.
2. 영어는 대소문자를 구분하지 않고, 단어 경계에서만 찾는다.
3. 한글은 뒤에 붙는 조사를 허용한다. "카나리만"에서 "카나리"를 찾는다.
4. `<pre>`, `<code>` 안에는 밑줄을 긋지 않는다.

### 초기 사전

AI/LLM, 보안, 개발 기초 분야의 용어 150~300개. LLM으로 초안을 만들고 사람이 검수한다. TTA 정보통신용어사전 등 저작권이 있는 사전의 문구는 그대로 옮기지 않는다.

## 5. LLM 프롬프트

### 입력

- 용어
- 용어가 들어 있는 문단 하나 (답변 전체가 아니다)
- 사전의 뜻 후보 목록 (드래그 경로에서 사전에 없는 단어면 비어 있다)

### 출력 형식

첫 줄은 판정, 그 아래는 설명이다.

```
SENSE: canary.security
이 문단에서 '카나리'는 실제 공격 대신 로그에 한 줄만 남기는 무해한 표식을 말합니다.
진짜 비밀번호를 훔치는 대신 "여기까지 공격이 닿았다"는 흔적만 남겨서, 위험 없이 공격이 성공했는지 확인하는 용도입니다.
```

- 판정 줄은 `SENSE: <뜻 id>` 또는 `SENSE: NEW`다. 화면에는 표시하지 않는다.
- 판정을 JSON이 아닌 첫 줄 텍스트로 받는 이유는 스트리밍 중 줄바꿈이 오는 순간 판정을 알 수 있기 때문이다.

### 설명 제약

- 한국어로 3~4문장.
- 첫 문장은 "이 문단에서 X는 ~라는 뜻입니다" 형태로 시작한다.
- **설명 안에 다른 전문용어를 새로 끌어오지 않는다.** CS적 공백을 줄이려는 설명이 또 다른 공백을 만들면 안 된다.

### 사전 항목 초안 생성

"사전에 추가" 버튼을 누를 때만 두 번째 호출을 해서 4절 형식의 항목 초안을 만든다. 사용자가 확인한 뒤 저장한다.

## 6. 사용 흐름

### 흐름 A: 밑줄 친 용어 클릭

1. `answerWatcher`가 답변 완성을 감지하면 `highlighter`가 사전 용어에 밑줄을 긋는다.
2. 사용자가 용어를 클릭한다.
3. 팝업이 즉시 뜨고 사전의 `short` 뜻을 보여 준다. 뜻이 여러 개면 모두 보여 준다.
4. 동시에 background에 `{용어, 문단, 뜻 후보}`를 보낸다.
5. 판정 줄이 도착하면 해당 뜻만 남기고 나머지는 흐리게 처리한다. 그 아래에 문맥 설명을 스트리밍으로 이어 붙인다.

### 흐름 B: 드래그로 질문

1. claude.ai 페이지 어디서든 단어를 드래그하면 "?" 버튼이 뜬다. 답변 영역에 한정하지 않으므로 DOM 선택자가 깨져도 이 기능은 동작한다.
2. 버튼을 누르면 팝업이 뜬다. 사전에 있는 단어면 흐름 A의 3단계부터 똑같이 동작한다.
3. 사전에 없으면 "사전에 없는 용어예요. 설명을 불러오는 중…"을 띄우고 뜻 후보 없이 LLM을 호출한다.
4. 설명이 끝나면 **[사전에 추가]** 버튼이 나타난다. 누르면 항목 초안이 생성되고, 사용자가 확인하면 저장된다. 이후 그 용어에도 자동으로 밑줄이 그어진다.

### 캐시

같은 `(용어, 문단)` 조합의 결과는 탭이 열려 있는 동안 메모리에 둔다. 같은 밑줄을 다시 눌러도 API를 다시 호출하지 않는다.

## 7. 오류 처리

원칙: **사전 뜻은 항상 보여 주고, LLM 설명은 있으면 더해지는 보너스로 취급한다.**

| 상황 | 처리 |
|---|---|
| API 키 없음 | 사전 뜻만 표시하고 "문맥 설명을 보려면 API 키를 설정하세요" 링크를 보여 준다 |
| 401 (잘못된 키) | 위와 같고, 문구만 "API 키를 확인해 주세요"로 바꾼다 |
| 429, 529, 네트워크 오류 | 사전 뜻은 유지하고 "설명을 불러오지 못했어요 [다시 시도]"를 표시한다 |
| 판정 줄 형식 오류 | 판정 없이 뜻 후보를 모두 보여 주고, 설명 본문은 그대로 표시한다 |
| claude.ai DOM 변경으로 답변 영역을 못 찾음 | 밑줄만 사라지고 드래그는 계속 동작한다. 콘솔에 경고를 남긴다 |

## 8. 테스트

### 자동 테스트 (Vitest + jsdom)

| 대상 | 확인할 것 |
|---|---|
| `dictionary` 용어 찾기 | 긴 alias 우선, 한글 조사 허용, 영어 단어 경계, 사용자 항목 병합 |
| `highlighter` | 텍스트 노드만 감싸고 기존 HTML 구조를 유지, `<pre>`/`<code>` 건너뜀, 같은 답변을 두 번 처리하지 않음 |
| 판정 줄 파서 | 스트리밍 조각이 임의 위치에서 잘려 와도 판정과 본문을 올바르게 분리, 형식 오류 시 "판정 없음" |
| `explainTerm` | `fetch`를 가짜로 바꿔 401, 429, 네트워크 오류가 7절의 각 상태로 이어지는지 확인 |

**고정 입력(fixture):** 1절의 "설계 원칙과 가정" 문단을 claude.ai 답변 HTML 형태로 저장해 쓴다. "카나리", "정적 탐지기", "택소노미"에 밑줄이 그어지면 통과다.

### LLM 뜻 판정 평가 (실제 API, 수동 실행)

뜻이 여러 개인 용어로 `{문단, 용어, 정답 뜻 id}` 20건을 만들고 스크립트로 Haiku 4.5를 호출해 정답률을 잰다. **통과 기준: 90% 이상.** 프롬프트를 바꿀 때마다 다시 돌린다. 비용과 비결정성 때문에 자동 테스트와 분리한다.

### 수동 확인 (claude.ai 실사용)

1. 답변 스트리밍이 끝난 뒤 밑줄이 생긴다.
2. 클릭하면 팝업이 1초 안에 뜬다.
3. 드래그로 질문한 뒤 사전에 추가하면 밑줄이 생긴다.
4. API 키가 없어도 사전 뜻이 보인다.
5. 팝업 모양이 claude.ai CSS 때문에 깨지지 않는다.

## 10. 지식 데이터 공유 방침

별도 프로젝트로 학습 튜터("괴짜들을 위한 사전", 문제 중심 설명 + 개념 지도)를 구상하고 있다. 두 제품은 **큐레이션된 지식 데이터를 공유하고, 코드와 저장소는 분리한다.**

v1 단계에서 지킬 것은 두 가지뿐이다. 공용 저장소는 만들지 않는다. 사용처가 아직 하나이므로 두 저장소를 동기화하는 비용만 생긴다.

1. **사전 데이터는 `dictionary/` 디렉터리에만 두고 코드와 섞지 않는다.** 나중에 떼어 낼 경계를 미리 그어 두기 위함이다.
2. **항목 `id`와 `senses[].id`는 한 번 정하면 바꾸지 않는다.** 튜터의 개념 노드가 이 id로 사전 항목을 가리킨다.

튜터 쪽 요구사항은 기존 필드를 바꾸지 않고 **필드를 더하는 방식**으로 수용한다. JSON에서 필드 추가는 하위 호환이므로 Viberacy는 모르는 필드를 무시하면 된다.

```json
{
  "id": "canary",
  "aliases": ["카나리", "canary"],
  "senses": [ /* Viberacy가 쓰는 부분 */ ],
  "concept": {
```
